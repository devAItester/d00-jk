# HTML/CSS optimization: reference vs generated output

## Цель

Проверить, насколько наш генератор действительно воспроизводит модель XXIIVV Wiki, и отделить визуальное сходство от качества и сложности исходного HTML/CSS.

Это не исправление production и не попытка сделать код «современнее» ради самого обновления. Цель — найти объективно лишнюю сложность и сохранить те решения референса, которые непосредственно определяют его поведение и визуальную модель.

## Контрольный материал

Для сравнения зафиксирована одна реальная страница референса:

- upstream: `XXIIVV/oscean`
- страница: `site/home.html`
- CSS: `links/main.css`
- контрольный commit: `7ae8d4a3329fab51389d70fad330717540fb0f57`

Копия исходников сохранена в `development/html-css-optimization/reference/`.

## Что сравниваем

Сравнение ведём по нескольким уровням:

1. **HTML output** — какая разметка фактически попадает в браузер.
2. **CSS** — геометрия, единицы измерения, наследование, reset и layout-модель.
3. **Генератор** — насколько сложна логика, которая создаёт этот output.
4. **Семантика и стандарты HTML** — есть ли объективные проблемы независимо от визуального результата.
5. **Accessibility** — элементы, атрибуты и структура документа.
6. **Производительность и стабильность layout** — только там, где это следует из структуры, а не по предположению.
7. **Fidelity** — что необходимо оставить для воспроизведения поведения референса.

## Первые результаты

### 1. CSS не является главным расхождением

Наш `_includes/style.css` практически буквально совпадает с upstream `links/main.css`.

Следовательно, тезис «наш CSS слишком современный/сложный относительно референса» пока не подтверждается.

У референса есть одно существенное дополнение на верхнем уровне:

```css
html {
  background-image: url(../media/icon/halftone.gif);
  background-repeat: repeat;
  background-attachment: fixed;
}
```

Это отдельное визуальное свойство, а не другая layout-модель.

### 2. В референсе units есть

Отсутствие единиц в HTML не означает отсутствия единиц в CSS.

Основная геометрия референса построена на `px`:

- `30px`
- `45px`
- `50px`
- `60px`
- `624px`
- `400px`
- `25px`
- `15px`
- `10px`

Есть также проценты, `calc()`, `vw` и другие CSS-механизмы.

Поэтому замена `px` на `rem` только ради формальной «современности» не является целью этой оптимизации.

### 3. Главный кандидат на оптимизацию — генератор меню

Наш `_includes/nav.html` содержит:

- вычисление текущего пути;
- вычисление parent/grandparent;
- несколько промежуточных массивов;
- три прохода по `site.pages`;
- отдельные проверки существования трёх колонок;
- повторное вычисление структуры узла в каждом проходе.

При этом конечный HTML меню остаётся обычным:

```html
<nav>
  <ul>...</ul>
  <ul>...</ul>
  <ul>...</ul>
</nav>
```

То есть сложность находится преимущественно **до браузера**, в Liquid-генераторе.

Это пока не объявляется ошибкой: генератору действительно необходимо вычислить локальный срез дерева. Но это первый участок, где есть смысл проверить, можно ли получить тот же output меньшей алгоритмической и шаблонной сложностью.

### 4. Референс — не идеальный HTML-эталон

Контрольный HTML референса содержит исторические и page-specific решения:

- inline `style`;
- page-specific `<style>`;
- явные размеры изображений;
- пустой `<ul></ul>`;
- несколько элементов, предназначенных для конкретной страницы;
- старые HTML-приёмы вроде `<center>` уже предусмотрены общим CSS.

Поэтому правило эксперимента:

> **Воспроизводить намерение и поведение референса, а не автоматически копировать каждую историческую деталь его исходника.**

И наоборот:

> **Не считать любое отличие нашего HTML преимуществом только потому, что оно выглядит современнее.**

## Метод работы

После каждого существенного изменения фиксируем:

- что изменено;
- какую проблему оно решает;
- почему исходный вариант был хуже;
- влияет ли изменение на output;
- влияет ли оно на визуальное поведение;
- влияет ли оно на accessibility/валидность;
- есть ли цена или новый компромисс.

Production на этапе исследования не меняется.

## Рабочий принцип

Визуально отличный прототип не является основанием прекращать оптимизацию.

HTML и CSS здесь являются частью архитектуры: они определяют не только внешний вид, но и размер/сложность output, layout-модель, устойчивость документа, accessibility и количество логики, которую приходится поддерживать генератору.

Поэтому задача — не «переделать рабочий сайт», а найти минимальную и устойчивую реализацию того же результата.
